Shared functional coverage

  • Report discovery: client/business categories, unchanged card-based report selection, report search, All reports, Schedules and History.
  • Client selection: 52 fictional fixtures; name/email/CRN search; all-page selection, select-all matching results, selection across pages, remove/clear, selected-only view, five overlapping groups with member selection and deduplication. Sorting by name/current/invested value. Page navigation, Go to page and 10/20/50/100 rows.
  • Filters: Total Current Value, Total Invested Value, MF Profile, MF Current Value, MF Invested Value, Broking Profile, Tracker Sync, Tracker Value, COB Opportunity Value, App Version and Last Seen At. Typed values, multiple conditions, apply and clear.
  • Periods: Last 7/30/90 days, Last month, Last quarter, Last 6 months, Previous FY and Custom range for one-time reporting. Schedule excludes Custom range.
  • Snapshot dates: As on run date and As on a fixed date; schedules retain run-date behavior. Historical reconstruction is not simulated.
  • Scheduling: Daily, Weekly, Monthly, Quarterly and Annually; Monday–Sunday; monthly/quarterly days 1–28; annual month with first-day execution; all 24 hours with five-minute intervals; required name. Quarterly month set remains Jan/Apr/Jul/Oct.
  • Schedule defaults: existing report-specific default times are retained. Changing recurrence retains the observed date-window defaults, with an explanatory notice. ELSS stays a fixed financial year; no new rolling-year rule is invented.
  • Schedule management: create, view, edit recipients/configuration, save, pause/resume, Run now and delete with confirmation. Editing locks report type and format, matching the observed editor.
  • History/results: per-request configuration and per-client statuses; single sample download; multi-client ZIP download; no-data, failed and partial-success states; retry failed items; successful items remain available.
  • Validation: no client selected, single-client constraints, missing date/financial year/folio/opening date/name, reversed custom dates and missing email recipients. UI date-order and recipient errors are proposed improvements; backend validation was not reimplemented.
  • Interactions: initial loading, in-progress submission with duplicate-action prevention, success/empty/error scenarios, preserved configuration when closing and reopening the modal, keyboard focus containment and Escape behavior.

Visual fidelity

Live screens were rechecked for report cards, client tables, configuration controls and schedule actions. The implementation uses the observed Lato typography, primary purple #6725F4, selected text #5419D1, lavender #F8F4FF, white surfaces, gray dividers, 8px buttons, rounded cards, pill selectors and status badges. Original Wealthy logo and navigation SVG assets are included.

The original production component package was not supplied. These are locally recreated components matching the observed visual language, not an import of Wealthy’s production React/component library. The original Adobe Lato stylesheet is referenced; an internet connection is needed for the exact web font when it is not already cached.

Prototype boundaries

  • No API calls to Wealthy, real emails, financial report generation or scheduled execution. Sample CSV, XLSX and PDF files contain configuration and fictional identity only, clearly marked as prototype samples.
  • Jobs and schedules persist in the browser’s local storage separately for each variation. Prototype controls can reset them. Reloading returns to the catalog; unfinished form drafts do not persist across reloads.
  • Calendar reference is 15 October 2026. Next-run labels are illustrative, not a verified production timezone calculation.
  • PMS’s scheduled form intentionally preserves the observed absence of Account Opening Date. The audit identified this inconsistency for engineering review; the prototype does not invent a new server requirement.
  • Folio entry stays manual. Family membership stays governed by the underlying report; a new family-management workflow is not added.
  • Surrounding global navigation is visual context. Reports functionality is interactive; unrelated products, profile and global search are outside this prototype.
  • Client, schedule and history pagination operate on local fixture records; production server-side loading is represented by the loading state.

Suggested comparison tasks

  1. Generate Holdings PDF for one client with Cashflows included.
  2. Select a group and download Mutual Fund Holdings as Excel.
  3. Email Capital Gain Loss for a custom period to two clients. Try a reversed range first.
  4. Create an annual ELSS schedule and check that the selected FY is visible in the review.
  5. Remove a selected client while configuring; then add a different client without losing the current settings.
  6. Use the partial-success scenario, retry the failed report and retrieve all ready files.

Compare completion time, missed settings, confidence in recipient selection, scrolling effort and recovery from mistakes. Prefer the layout that performs better with real partner tasks; these prototypes do not establish a usability-test winner.
